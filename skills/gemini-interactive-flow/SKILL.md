# Gemini Interactive Flow

本技能專為在 Codex 桌面端使用 Gemini（包含 `ccs-gemini/*` 或自訂代理模型）設計，用以克服通用模型在桌面端缺乏「即時進度反饋」與「內嵌互動式元件」的預設行為差異。

---

## 一、階段進度即時回報（Progress Milestone Updates）

### 1. 核心節奏：報進度但不中斷
- **一段落回報**：執行耗時、多步驟或複雜任務時，每完成一個階段目標或重要檢查點，應以**精簡的單一段落**回報進度，讓使用者即時掌握當前狀態，避免長達數十秒至數分鐘的無聲黑箱。
- **持續推進（不暫停）**：輸出進度摘要後，**立即自動繼續執行後續動作**，不需要停下來等待使用者回覆確認（除非遭遇不可逆的破壞性操作或真實阻塞條件）。

### 2. 進度段落撰寫原則
- **精準俐落**：以 1–3 句話交代「剛剛完成了什麼」與「接下來進行什麼」。
- **事實優先**：帶出關鍵數據、路徑或測試結果，不寫冗長的虛詞或推論。

## 二、內嵌互動式視覺化能力（Inline Visualization Contract）

當任務涉及以下情況時，主動製作成 Codex 桌面端原生支援的**互動式卡片**：
1. **介面設計與主題配色挑選**（深淺主題、高對比監控）。
2. **參數動態調校與試算**（採集頻率、緩衝區計算）。
3. **設備與產線儀表板即時預覽**（動態數據跳動、燈號告警）。
4. **向使用者提出問題與方案決策（Q&A & Decision Cards）**。

### 1. 提問與方案決策必觸發（Interactive Decision & Q&A Cards）
- **拒絕純文字問答**：當模型需要**向使用者提問確認、提出多個選擇方案（如架構選型 A/B、通訊協議決策、UI 排版選項）**，或**解答使用者帶有方案比較的問題**時，**禁止僅用純文字條列**，必須主動產出互動式決策卡片。
- **卡片必備結構**：
  - **核心決策標題**：明確指出問題焦點（例如「請確認採集逾時處理機制」）。
  - **可點選選項卡片**：提供單選按鈕或按鍵（Option Cards），點擊後下方即時展示該選項的「運作邏輯、效能影響、潛在風險或模擬畫面」。
  - **推薦標籤（Recommended）**：首選方案標註推薦，讓使用者可直接視覺確認或點擊選擇。
  - **一鍵複製操作列（Action Bar with One-Click Copy）**：
    卡片底部必須包含一鍵複製工具列，點選不同選項時動態組合成格式化指令（例如「我選擇方案 A：指數退避重試，請繼續實作」），使用者點擊「複製確認句」即可自動寫入系統剪貼簿（具備 `navigator.clipboard` 與 `execCommand` 雙備援），直接貼上送出，免去手動打字。
    *參考範本*：`templates/decision_card_template.html`

### 2. 輸出契約（Strict Fragment Contract）
- **純 HTML 片段**：只能包含局部標籤（如 `<div id="...">...</div>`、`<style>`、`<script>`），**嚴禁**包含 `<!DOCTYPE html>`、`<html>`、`<head>`、`<body>`。
- **獨立唯一根 ID**：片段外層必須有一個專屬 ID，所有的 CSS 選擇器與 JavaScript 操作皆以此 ID 為根（例如 `#my-widget .btn`），防止樣式外溢或命名衝突。
- **內置狀態與事件**：在 `<script>` 中以純 JavaScript 綁定事件（如點選按鈕、滑桿切換、主題更換），並直接修改局部 DOM 屬性實現即時互動反饋。
- **禁止外部連網**：僅允許內建樣式或經許可的 CDN 靜態資源，禁止在片段中調用外部 API（無 `fetch`、WebSocket）。

### 3. 檔案寫入與觸發語法
1. **寫入檔案**：將 HTML 片段儲存於本機可存取路徑（優先選擇任務環境中的視覺化目錄，例如 `~/.codex/visualizations/...` 或任務工作目錄下的 `.html` 檔案）。
2. **調用標記**：在回覆的文字中，以**單獨一行**輸出專屬觸發語法：
   ```text
   visualize{"path":"<本機絕對路徑>/<檔名>.html"}
   ```
   * 桌上型完整寬度預覽時，可加入參數 `"mode":"wide"`：
   ```text
   visualize{"path":"<本機絕對路徑>/<檔名>.html","mode":"wide"}
   ```
3. **語法禁忌**：**絕不可**將 `visualize...` 包裹在 Markdown 代碼塊（```）或引號內，否則桌面端客戶端無法捕捉該 Token。

## 三、Gemini 模型執行最佳化

1. **降低思考延遲（TTFT）**：
   - 透過 CC Switch 或代理調用具備思考能力的 Gemini（如 `gemini-3.7-flash` / `gemini-3.8-flash`）時，建議將推理強度設置為 `low`，確保文字串流秒出，階段性進度能隨打隨顯示。
2. **工具調用透明化**：
   - 模型在背景調用終端指令或檔案寫入工具時，應將工具輸出轉換為清晰的自然語言進度，而非直接丟出整大段原始 JSON 或終端日誌。
